# 信号落盘规范（companion 步骤4）

> SKILL.md 步骤4 引用本文件。信号落 `user/signals/<signal_id>.yaml`。

**信号不是后台收件箱里待处理的 pending 记录，也不是从文章摘个金句套 schema 落盘。** 信号是会员读后产生的真实决定，或从一个不显眼的点**锐化出的有语境、有张力、能推动真实迭代的命题**。

## 落盘形态

首跑时发现落盘容易变得机械——记下一句漂亮话，标个状态，就算"有信号了"。下面这几条是为了防这个：

- **诚实标 `state`**：`candidate`（锐度够但怎么推进未定，不假装收敛）/ `acted`（已推动真实行动）/ `revisited`（外部回流带回兑现 **或** 已有根本立场被新事实重新校准——见下方"revisited 子型"）。**不假装进度。**

  > **revisited 子型澄清**（实测得出）：
  > revisited 不只是"外部回流"的代名词。**已有根本立场被一次新事实主动重新校准、并把张力收编进自己叙事**，也是合法的 revisited——这种"再确认"是有价值的真实信号，不要求必须是"新决定"才算伴读成功。
  > 判据：会员**动用自己的世界观主动消化了一个本可证伪它的事实**（不是礼貌点头说"嗯有道理"）。

- **放进真实语境**：记 `trigger_context`（哪次伴读/哪句话锐化出来的，具体到原话）。张力分两类：
  - `tension_internal`（会员立场内部的张力，**会员自己说出来的**）——有就记，常是信号有价值处。
  - `tension_cross`（与会员别的信号之间的跨上下文张力，**由陪读方主动构造**）——**可选，首跑无别的信号可对照时留空**。
  - ⚠️ **宁可空，不可编**：实测中出现过为了凑"最有价值处"而自创一条会员没说过的张力。**编造张力比空着坏**——它会让整份信号档案失去可信度，而空着只是少一条。没有真张力就空。

- **不替用户决定 / 不强求引发行动**：**发现信号本身就是本工具的终极目的**，引发行动更好但**不强求**。`owner` 写清行动归属（通常=会员本人），工具职责到"发现并锐化信号"即完成。

- **锐化优先于摘金句套 schema**：好的锐化是多轮对话把一句模糊的抱怨（"最近沉不下心"）变成一个有分量、能验证的命题。摘金句只是搬运，锐化才是产出。

## schema

```yaml
signal_id: <member_id>-YYYYMMDD-NN    # 带 member_id 前缀，标识归属
member_id: ""
title: ""                             # 一句话点出这个信号/命题
state: candidate                      # candidate(待推进,不假装收敛) / acted(已推动行动) / revisited(回流带回兑现)
source_article: ""                    # 触发的那篇内容 + 原文链接
trigger_context: ""                   # 哪次伴读/哪句话锐化出这个信号(具体到原话)
decision_text: ""                     # 会员的真实决定/锐化出的命题(带会员自己内容,不是金句、不是礼貌点头)
tension_internal: ""                  # 会员立场内部的张力(会员自己说的);有则记
tension_cross: ""                     # 与会员别的信号之间的跨上下文张力(陪读方构造);可选,无则空。宁空勿编
decision_kind: cognition              # cognition/action/share 是例子,开放;别为归类硬套
owner: ""                             # 行动归属(通常=会员本人);工具不替执行、不预设答案、不催办
created_at: ""                        # ISO 时间
followup_note: ""                     # 外部回流被动填,留空正常,工具不催办
next_visible_at: ""                   # 可选:会员自定回看时间(非巡检字段,见下)
```

> ⚠️ **`next_visible_at` 是会员自定的、可空的、不被巡检的**——只是会员自己想回看，不是催办钩子。
>
> 这条要单独说，是因为很容易被写成"活跃信号必须有回看时间、N 周内必须闭环"的巡检字段。那样做会让工具从"陪读"滑向"催办"，而催办正是会员最容易弃用的行为。**信号可以永远停在 candidate，那不是失败。**

## 信号锐化到命题级之后

若某个信号锐化成了值得长期跟踪的命题（跨多篇文章反复出现、与会员的其它判断产生张力），它就超出了单次伴读的范围。

**本工具不接管这类命题的所有权**——它只负责发现和锐化，把它交还给会员，由会员决定放进自己的什么系统里跟踪。工具侧只保留信号档案本身。
